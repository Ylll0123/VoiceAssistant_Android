# HardlySeek · AI 语音助手（C3 课题）

Android 课程大作业 —— C 档「挑战级」课题 C3：本地智能语音助手。
应用在桌面上显示为 **HardlySeek**。

## 项目简介

v4.0 起，这个 App 的分工被压到最简单的三件事：**听清人话 → 交给大模型 → 需要动手就调工具**。

- **主课题**：C3 本地智能语音助手
- **伴生模块**：P3 通知提醒中心（AlarmManager 精确闹钟 + 通知操作）

做到 v3.8 时，工程里还有一整套本地规则引擎、语料库、模糊匹配、天气数据源。
它们能做「报时间、算 12 乘 8、讲个笑话」，但也仅此而已：稍微绕一点的问题就答不上，
而且**两套逻辑会互相打架**（本地先上屏、云端回来再顶掉；本地硬答，大模型插不进话）。

v4.0 把本地那套全部删掉，只留下大模型一条路：

> 算数、换算、天气、出行、查资料、讲道理、闲聊 —— 全部由模型直接回答；
> 需要真的动这台手机（建提醒、计时、开手电筒、报电量、停止朗读）——
> 由模型通过 **function calling** 调用本机工具。

三个原则：

1. **AI 为中心**：不再有「本地能答就本地答」的分支，只有一条调用链。
2. **离线就明说**：没网时不做假动作，进离线模式并拦住发送，网络一回来自动恢复。
3. **数据按账号隔离**：对话记录、提醒各自按账号分库，换账号就换一本账。

## 当前功能

### 一、强制登录

- 没有游客入口：没登录直接进登录页，返回键也退不出去
- 本地账号（PBKDF2 加盐，`data/Passwords`），不联网、不上传
- 账号是数据分区的键：对话记录、提醒、设置都按账号走

### 二、语音：长按说话

底部没有麦克风按钮了。

- **按住输入框**开始收音，**松手**结束识别，**上滑**取消（滑回去还能救）
- 不按的时候**不会录任何声音**——这是和以前「连续对话」最大的区别
- 识别结果只**填进输入框**，还要点一下发送：说错了还有机会改
- 播报用系统 TTS，可在设置里关掉「语音播报」

### 三、对话：一个大模型 + 六个工具

所有问答走同一条 `/chat/completions`（OpenAI 兼容协议，默认智谱 GLM-4-Flash-250414）。
模型判断要动手时返回 `tool_calls`，App 执行完把结果作为 `role=tool` 再发一轮，
最多 4 轮，然后给用户一句人话。

| 工具 | 用户会怎么说 | 实际做了什么 |
|---|---|---|
| `create_reminder` | 提醒我今晚八点交作业 | 写 SQLite + 排精确闹钟 |
| `list_reminders` | 我有哪些提醒 | 读未到点的提醒 |
| `cancel_reminder` | 把交作业那个提醒取消 | 按关键词匹配后取消 |
| `set_timer` | 定个十分钟的闹钟 | 倒计时提醒 |
| `device` | 开手电筒 / 声音小一点 / 电量多少 / 打开微信 | 调系统服务 |
| `stop_speaking` | 别念了 | 立刻停止 TTS |

模型不擅长表示时间，所以约定它传 `yyyy-MM-dd HH:mm` 的**本地时间字符串**，
当前时间写进 system 提示词。解析失败就当「没说时间」，让它再问一遍，绝不瞎猜。

### 四、多会话（对话记录）

左上角三条杠拉开左侧抽屉（占屏宽 4/5）：

- 每条对话**由 AI 起标题**（另发一次很小的请求，失败就用首句前 12 个字）
- 每条对话**相互独立**：独立的上下文、独立的落盘键
- 可以切换、可以新建、长按可删（删前再确认一次）
- 全部按账号隔离，换账号看不到别人的记录

### 五、网络感知（App 的根）

标题 **HardlySeek** 正下方一行：

- 有网：**绿点 + 在线**；没网：**红点 + 离线**
- 思考的时候，这一行被「正在想… / 正在听…」**顶掉**（同一个位置，不撑高顶栏）
- 网络状态**实时变**：开着 App 断网 8 秒内变红点，网络回来自己变绿
- 检测本身**完全不在界面上体现**，用户只会看到圆点变色
- 离线时：发消息、长按说话都被拦住并给出提示，不会在超时里干等

实现是「系统回调 + 周期自检」双保险：`NetworkCallback` 负责快，
每 5 秒（离线时 3 秒）自己问一次系统负责准——实测只靠回调时，
从有网切飞行模式界面会一直停在「在线」。

### 六、编辑与删除：只对最后一条

- **长按自己的气泡**弹「修改 / 删除」，单击不做任何事（避免误触）
- **只有最后一条发出去的消息能改能删**，改中间的会让后面的回答对不上；
  删掉最后一条后，上一条自动变成「最后一条」，以此类推
- 修改**直接在这条气泡里进行**（气泡自己变成输入框 + 保存 / 取消），不另开对话框
- **改完自动重新回答**：旧答案作废，用新问题重新问一次，界面上先看到新问题、
  再填进新答案——不会出现「问 A 答 B」
- 删除**先问一遍**确定还是取消

### 七、提醒中心（P3 伴生模块）

- SQLite 持久化 + AlarmManager 精确闹钟（Android 14+ 用 `USE_EXACT_ALARM`）
- 重复提醒（每天 / 每周）在触发瞬间就把下一次排上，不依赖下次打开 App
- 通知上直接「10 分钟后再提醒」「知道了」
- 重启 / 覆盖安装后自动重排闹钟

### 八、界面

- 顶栏：左三条杠（设置页里变返回箭头）· 中间标题 + 在线状态 · 右齿轮
- 没有底部导航、没有功能页、没有垃圾桶和刷新键
- 四语言：中 / 英 / 日 / 韩（自有 `LocaleHelper`，不跟系统语言走）
- 设置只留最常用的：回答方式 / 语音播报 / 语言 / 清空对话 / 账号 / 关于

### 九、外部调用入口

```bash
adb shell am start -n com.example.voiceassistant/.ui.VoiceAssistantActivity --es query "现在几点"
```

`launchMode=singleTop` + `onNewIntent`，连续调用也在同一段对话里，上下文不断。

## 一轮问答怎么走

```
用户说话 / 打字
   │
   ├─ 离线？→ 提示「还没连上网络」，不发送
   │
   ▼
AiChat.ask(history, input)
   ├─ system = 人设 + 当前时间 + 回答风格
   ├─ POST /chat/completions（带 tools，tool_choice=auto）
   │
   ├─ 模型返回 tool_calls？
   │     ├─ 是 → AiTools 执行 → 结果作为 role=tool 再发一轮（最多 4 轮）
   │     └─ 否 → 拿到文字答案
   │
   ▼
上屏 + 落盘（按会话 id）+ 可选播报 + 必要时让 AI 给这段对话起标题
```

## 分层与目录结构

```
app/src/main/java/com/example/voiceassistant/
├── core/AiChat.kt          一轮问答的全部智能：组消息、发请求、转工具、收敛回答
├── tool/AiTools.kt         六个工具的声明（JSON Schema）与执行
├── handler/llm/            云端配置、协议解析、人设、连通性测试
├── network/                网络状态感知 + HTTP
├── data/                   账号 / 会话 / 会话存储 / 设置 / 消息模型
├── reminder/               提醒中心（P3）：模型、SQLite、状态机、闹钟、广播
├── service/                ASR / TTS / 设备与音频控制
├── installer/              装完清理安装包
├── bus/                    进程级同步事件总线（提醒到点通知界面用）
└── ui/                     只做接线：Activity / ChatFragment / 两个 Adapter / 登录 / 设置
```

层与层之间只认两个接口：`reminder/ReminderPort`（提醒）和工具层的 `schema`（能力清单）。
想换存储、换模型、加工具，都不用动调用链。

## 几个关键取舍

**为什么不留本地兜底答案**
留了就必须判断「本地这句答得够不够好」，而这个判断本身永远不准：
会出现本地硬答、把大模型的正确回答挡在外面。v4.0 直接把这条路删掉，
没网就明确告诉用户没网——诚实比虚假的可用性重要。

**为什么工具循环最多 4 轮**
模型有时会连着调十次工具（尤其它以为失败了）。4 轮足够覆盖「建提醒 → 回读确认」，
再多就是在绕圈，一次对话要烧十次请求。

**为什么不做答案缓存**
带工具调用的回答依赖「当时手机的状态」（几点、有没有提醒、电量多少）。
缓存下来的答案下次原样复活，看着像灵异事件。

**为什么网络要自己巡检**
见上文「网络感知」：只信 `NetworkCallback` 会漏掉飞行模式、Wi-Fi 连着没外网这些场景。

**为什么只有最后一条能改**
改了中间那句，它后面那串回答就全部失义。只允许改最后一条，
改完顺手作废旧答案重新问一次，上下文永远是自洽的。

## 测试

```bash
./gradlew testDebugUnitTest --offline   # 115 个单测，全绿
./gradlew lintDebug --offline           # 0 error
```

单测只测**纯函数**（不需要 Android 运行时）：

- `AiChatTest`：请求体结构、工具调用解析（标准 / 旧式两种写法）、起名兜底
- `AiToolsTest`：工具清单是合法 JSON、六个工具齐全、时间字符串解析的六种写法
- `ChatSessionTest`：改问之后旧答案作废、历史只取这条之前、上下文不断
- `ConversationStoreTest`：会话与消息的编解码（引号换行不能把数据写坏）
- `CloudLlmHandlerTest`：地址拼接、JSON 转义、错误翻译、三代旧人设迁移
- `ReminderCenterTest` / `ReminderRepeatTest`：提醒状态机与重复规则
