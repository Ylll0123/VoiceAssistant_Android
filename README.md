# HardlySeek · AI 语音助手（C3 课题）

Android 课程大作业 —— C 档「挑战级」课题 C3：本地智能语音助手。
应用在桌面上显示为 **HardlySeek**。

## 项目简介

v4.0 起，这个 App 的分工被压到最简单的三件事：**听清人话 → 交给大模型 → 需要动手就调工具**。
v5.0 又把「动手」这半件做成了**供需总线**：能力只实现一次，本地指令和大模型工具调用共用。
v5.1 把「听清人话」补上：识别按整句来，复合句交给 AI 拆开做；发消息确认后全自动完成。
v5.2 修两处实测问题：全自动发送没进聊天页就绝不写字；语音唤醒不再「开关亮着叫不醒」。
v5.3 试过「跨应用悬浮助手」，实测价值不足，v5.4 整块移除。
v5.4 发消息改成**只填不发**：程序进去找人、把话填进输入框，发送键留给人点。
v5.5 修「只能发一次」和「没发出去却说发了」；唤醒接入**讯飞 AIUI 离线唤醒**（系统识别继续做兜底）。
v5.6 **整块删掉语音唤醒**（连同灵敏度/提示音/引擎/保活那套设置），设置页只剩三项；
长按说话**松手就发**；语音播报重做（没声音能说出为什么）；闹钟改设**系统时钟**，音量分媒体/铃声/闹钟，新增「播放音乐」。
v5.7 补齐语音助手最缺的两件事：**打电话**（姓名→通讯录→拨号，没权限退拨号盘）和**导航**；
发消息的本地句式放宽（「跟妈妈说一声…」也认）；把 12 个「注册了但调不到」的服务
要么接上、要么删掉，工具从 19 个变成 27 个。
v5.8 修「连发两次就卡住」「说发了其实没跳转」：后台不再单线程、分享结果要**验证**、
内容先落剪贴板；QQ/微信按「上次用的那个」区分；发出去的内容按原文处理（问句不回答）。
v5.9 补四件系统能力（**截屏 / 剪贴板 / 勿扰 / 拍照**）和两个补救动作（**再试一次、再念一遍**），
同时把「跳转类指令」的假成功一并修掉：面板、相机都要**看见界面真的换了**才算成功。

- **主课题**：C3 本地智能语音助手
- **伴生模块**：P3 通知提醒中心（AlarmManager 精确闹钟 + 通知操作）

做到 v3.8 时，工程里还有一整套本地规则引擎、语料库、模糊匹配、天气数据源。
它们能做「报时间、算 12 乘 8、讲个笑话」，但也仅此而已：稍微绕一点的问题就答不上，
而且**两套逻辑会互相打架**（本地先上屏、云端回来再顶掉；本地硬答，大模型插不进话）。

v4.0 把本地那套全部删掉，只留下大模型一条路。
v5.0 再把「本地优先」以另一种方式加回来：不是拿本地规则去**答题**，
而是拿它去**执行明确指令**——「开手电」「定八点提醒」「算 12 乘 8」不用联网也不用等模型，
问答、翻译、解释这些依然只有模型能做。

三个原则：

1. **能力只写一次**：一个 `Supply` 同时挂在本地路由和大模型工具上，不搞两套。
2. **本地只做确定的**：句式固定、参数明确的指令本地办；其余一律交给模型，宁可漏判不可错判。
3. **数据按账号隔离**：对话记录、提醒各自按账号分库，换账号就换一本账。

## 当前功能

### 一、强制登录

- 没有游客入口：没登录直接进登录页，返回键也退不出去
- 登录页只有品牌名和表单，不放说明性小字
- 本地账号（PBKDF2 加盐，`data/Passwords`），不联网、不上传
- 账号是数据分区的键：对话记录、提醒、设置都按账号走

### 二、语音：长按说话

底部没有麦克风按钮了。

- **按住输入框**开始收音，**松手**结束识别，**上滑**取消（滑回去还能救）
- **单击输入框能把光标精确放到点的那个字中间**：自己按坐标算插入点
  （`ui/CursorMath` 是纯函数，能单测），补上 Android「首次点击只聚焦不定位」
  和多行行尾跳位这两种情况；拖动选字、光标手柄照常可用
- 不按的时候**不会录任何声音**——这是和以前「连续对话」最大的区别
- **单击输入框能正常定位光标、选中文字**：短按交给 `EditText` 自己处理，
  只有长按（超过 380ms）才起语音，滑动/抬手只在真的录音时才拦
- 识别结果**松手就发**，不用再点一次发送；说错了长按气泡改，改完自动重新回答
- 播报用系统 TTS，可在设置里关掉「语音播报」

**整句识别**：以前停顿阈值只有 1.2 秒，一句话说到一半换口气就被判「说完了」，
听起来就是「只识别到几个字」。现在：

- 完全静音 2.6 秒才收口，「可能说完」留 2.0 秒余量，最短录音 1.2 秒
  （`AsrManager` 的三个参数），句中换气不会再被截断
- 最终结果**不是无脑取第一条**：候选里若有一条以首选开头且明显更长，
  说明首选被截断，改取那条（`service/AsrPick`，纯函数可单测）
- 引擎报「超时 / 没匹配」但已经听到半句时，把半句交出去，而不是回「没听到声音」

### 三、一句话先过本地，办不了才找大模型

v5.0 加了**供需总线**：每个能力只实现一次，挂成 `域/动作`（`device/flashlight`、
`schedule/add_alarm`），**本地识别**和**大模型工具调用**落到同一份实现上。

```
用户这句话
  ├─ 有等着确认的发送？→ 「确认」就真发，说「算了」就丢
  ├─ LocalNlu 认得？   → 直接调总线，不联网、不花钱、不等待
  ├─ 云端 AI 关了？    → 直说「只能做本机操作」
  ├─ 没网？           → 直说「问答用不了」
  └─ 都不是           → AiChat.ask()，模型需要动手时再回调同一批服务
```

本地只认**句式固定、参数明确、错了也很明显**的指令，其余一律交给大模型——
「打开这个思路」不会被当成打开应用，「今天天气怎么样」不会本地硬答。
实测：断网状态下「现在几点」「打开手电筒」「12 乘 8」「提醒我明天八点交作业」
全部照常，只有问答类会回「现在没联网，问答用不了。」

**但语音输入是一整句话，不是一句短指令。** 如果规则只要句子里「含有」某个词就
抢着执行，「把亮度调暗一点然后放首歌」会被当成单纯调亮度、后半句直接丢了。
所以在线时本地走**整句模式**（`LocalNlu.route(..., strict = true)`）：

- 句子里有转折/并列/条件连接词（然后、接着、顺便、还有、如果、先…再…）→ 不认领，交给大模型拆开依次做
- 整句超过 24 字、只捞到一个关键词 → 不认领
- 短句、单一意图照旧本地秒回，不联网也不花钱
- 离线时退回宽松模式：宁可只做前半句，也不能整句作废

大模型那边也钉了一条硬规则（`AiChat.VOICE_INPUT_RULES`，写死不受自定义人设影响）：
输入来自语音识别，可能带同音字和断句错误，先把整句还原成最合理的意思再动手；
一句话里有几件事就依次全部做完。实测「把亮度调暗一点然后放首歌」会真的调低亮度、
再问你想听哪首，而不是只做前半句。

| 域 | 服务 | 本地认领的说法 |
|---|---|---|
| `schedule/` | add_alarm、add_todo、query、cancel | 提醒我八点交作业 / 10 分钟后叫我 |
| `device/` | flashlight、brightness、wifi_ctrl、bluetooth_ctrl、open_app、battery | 开手电筒 / 亮度调到 60% / 打开设置页面 / 打开原神 |
| `phone/` | call、navigate | 打电话给妈妈 / 打 110 / 导航到公司 / 带我去机场 |
| `audio/` | tts_speak、tts_stop、volume_ctrl、music_ctrl | 大声点 / 静音 / 别念了 / 放首歌 / 下一首 |
| `tool/` | calc、time、translate、weather | 帮我算 12 乘 8 / 现在几点 |
| `msg/` | send_text、query_can_send、query_history | 给妈妈发微信说我晚点到 / 跟妈妈说一声晚点到 |
| `study/` | word_query、word_review | （查词、抽查，交给模型） |
| `gen/` | short_sentence | 「帮我想句祝福」——只出成品，接 `msg/send_text` |
| `system/` | screenshot、clipboard、dnd、camera | 截个屏 / 复制刚才那段 / 打开勿扰 / 拍张照 |
| `context/` | clear、switch_prompt、retry | 清空对话 / 忘掉之前说的 / 再试一次 |
| `llm/` | toggle | 关掉云端 / 打开云端 |

`open_app` 不再只认一张手写的常用表：先从系统拉**全部有启动入口的应用**（`QUERY_ALL_PACKAGES`，
缓存 30 秒），常用名走内置表归一，其余按应用名模糊匹配，所以「打开学习通」「打开 YouTube」
也能开；找不到就明说找不到，不猜。打开成功会回一句「已经打开 XXX。」，不会闷头跳走。

模型那头只暴露 32 个工具（`schedule_add_alarm` 这种下划线写法，网关切 `/` 会 400），
`AiTools` 负责在两种命名之间来回翻译。

### 四、发消息：微信 / QQ（只填好，发送键留给你）

微信/QQ 的用户协议明确禁止自动化操作，而且它们按**行为特征**判定——
从进页面到点发送只隔几百毫秒，正常人做不到。自动提交换来的不是便利，是**封号**。

所以边界画在「输入框」：程序负责找人、进聊天页、把话填好，**最后一个动作由人做**。
风险上等同于复制粘贴，体验上只多一次点击。

```
给妈妈发微信说我晚点到
  → 打开微信 → 回首页 → 点进「妈妈」的会话（没有就搜索后点结果）
  → 把「我晚点到」填进聊天输入框
  → 停在这里，回一句「已经在微信里给「妈妈」填好了，点一下发送就行。」
  → 你抬手点一下「发送」
```

- **一步到位，不再问「确认吗」**：既然不替人提交，就没有"发错收不回"的风险，
  多问一句只是让用户多说一句话
- **填完不跳回来**：跳回本应用等于把用户从"正要按发送"的位置拽走，
  所以成功后**停在聊天页**，输入框里就是待发的内容
- **第二次也要能发**：上一轮填完，用户就停在这个人的聊天页。以前第二次会先「返回 → 首页 → 再点一次」，
  那条路上任何一步没人接（比如在「我」tab 上按返回会把整个微信退掉），表现就是「不跳转了」。
  现在先看**是不是已经停在这个人的聊天页**（底部有输入框 + 顶部标题正好是他），是就直接填，
  压根不做导航；必须导航时也不再一上来按返回，先点底部「微信 / 消息」tab
- **说「填好了」之前一定读回来**：填完再读一次输入框，读到一模一样才算成功；
  读不到就说「读不到输入框里的字，你看一眼」，**绝不说已发送**——程序根本没有点发送键
- **找不到人不降级分享**：分享页里根本选不出这个人，用户很可能顺手点了别人。
  这种「办不到」直接说「没找到」，不拿分享当遮羞布
- **进没进聊天页是硬门槛**。搜索框和聊天输入框都是 EditText，点联系人万一没响应，
  页面上还是搜索框，字就填到搜索栏里去了。现在靠三条判据区分：提示文字/id 像不像搜索、
  在屏幕上半还是底部、**是否位于搜索框下方**（搜索框里刚填进去的联系人名字和联系人同名，
  最容易被误点）。没拿到「明确的聊天输入框」就重试（坐标点击、QQ 资料卡点「发消息」、
  退回搜索页重搜），三次都不行就报失败并降级分享，**绝不把消息内容写进搜索框**
- **首页能直接点会话就不走搜索**：少两次跳页，也绕开上面那个坑
- **填字的两个坑**（v5.4 实测出来的）：
  ① 空输入框时无障碍返回的 `text` 其实是 **hint**（微信是「发消息」），拿它比对会误判
  「没填进去」，于是走粘贴兜底、把内容拼成「我晚点到到」——读取前先剔掉 hint 并 `refresh()`；
  ② 部分版本忽略 `ACTION_SET_TEXT` → 改走剪贴板「全选 + 粘贴」，
  选中长度必须按**真实内容**算，按 hint 长度会把已有文字截掉一半
- **读屏不可用**时退回系统 `ACTION_SEND` 分享面板：文字预填好，用户选联系人再点发送。
  同样不替人提交，只是「谁」要人点。这一步**必须验证**（见下），不再盲报成功
- 联系人**找不到就失败**，不问「是不是这个」；重名也不自己挑
- 无障碍判断以服务实例是否真的被系统 bind 为准，不看会残留的静态标志
- 问「为什么发不出消息」「能发微信吗」「检查一下发消息」会走 `msg/query_can_send`，
  直接报出**装没装 / 无障碍连没连上 / 分享通路能不能用**，不用猜
- 平台名兼容中文与别名（微信 / weixin / wechat / wx / QQ / 企鹅 / 包名）；
  说 QQ 却发到微信的根因是模型漏填 `platform`，现在用**用户原话**校对（`tool/PlatformHint`）
- **没说平台就沿用上次用过的那个**（`AppSettings.lastImPlatform`）。以前空值直接当微信，
  常用 QQ 的人每次都被带到微信、还得退出来重说一遍；现在「没说」和「说微信」是两件事
- **内容只按原文发**（`im/ImContent`）：问句也照发——「发消息给妈妈问她吃饭了吗」里的
  「吃饭了吗」是正文，不是要回答的问题；模型套的「好的，内容是：」「」引号、语音带来的换行
  统一剥掉，两条来路（本地规则 / 大模型）共用同一套规则
- **分享结果要验证**：`startActivity` 被系统拦下时不抛异常，所以以前「调用了就算成功」，
  用户看到的是「说带过去了，其实还在原地」。现在有读屏就看前台包名变没变，
  没有读屏就看**我们自己的界面有没有被盖住**；都没变化就改口说「内容已复制到剪贴板」——
  剪贴板是每一步都先写好的，那句话一定为真
- **连发两次不再卡住**：后台从单线程改成三条并发；`ImAutomator` 里**后来的请求赢**——
  新的进来就把 `generation` 加一，旧的在下个检查点自己退出让出锁，
  不用等它把十几秒的流程走完

本地识别也不再只认「给X发微信说Y」一种语序：「发微信给妈妈说我晚点到」
「帮我发条消息给妈妈：我晚点到」「用微信给妈妈发消息说我晚点到」都能认。
长内容不会因为超过 40 字被丢给模型——离线时模型不可用，那等于消息发不出去。

### 五、语音输入与播报

**输入**：长按输入框说话，松手识别完**直接发送**，不用再点一次发送键。
说错了长按气泡改——改完自动重新回答。

- 按住期间上滑 56dp 取消；识别按整句来（静音阈值 2.6s / 2.0s、最短 1.2s，
  1.2s 会在句中换气处截断，表现是「只识别到几个字」）
- 首选被截断时改判更长的候选（`service/AsrPick`）；超时但已经有半句，就用半句
- 离线不开麦：识别本身要走网络，问答类会回一句「没联网」

**播报**（v5.6 重做）：`service/TtsManager` 现在遵循「能念才说能念」。

以前这里只做一件事：`setLanguage(中文)`，失败就 `setLanguage(默认)` 然后当作没问题。
引擎答应得很痛快、实际一声不出，界面看起来一切正常——这就是「语音播报没效果」。

| 情况 | 现在怎么办 |
| --- | --- |
| 没有中文语音包 | 从 `engine.voices` 里显式挑一条 `zh` 声音；这台引擎没有就换一台再试（最多两台） |
| 媒体音量是 0 | 报 `MUTED`，给一个「调大音量」的按钮 |
| 一个引擎都没有 | 报 `NO_ENGINE`，引导去装 |
| 引擎把这句话吞了 | 看门狗按字数估时收尾，不会卡在「正在回答…」 |

- 设置里打开「语音播报」会**当场试听**，没声就按上面的原因弹一句能落地的引导
- 长回答按句读切段（每段 240 字）送引擎：`TextToSpeech` 单句上限约 4000 字，超了会被截断
- 换过系统语音引擎后回到应用会自动重探一次（`refreshIfNeeded`），不用重启

### 六、多会话（对话记录）

左上角三条杠拉开左侧抽屉（占屏宽 4/5）。抽屉出来时，后面的对话会**真的糊掉**
（Android 12+ 用 `RenderEffect`；老系统退回加深遮罩），视线自然落在列表上。

- **标题直接沿用用户问的那句话**（另发一次很小的请求让模型润色，失败就用原话前 24 字），
  上限 32 字、抽屉里可显示两行；不再把长问题截成看不出意思的半句
- 每条对话**相互独立**：独立的上下文、独立的落盘键
- 点一条切过去。**长按任意一条**，或点右上角那颗白底黑字的「编辑」，
  都能进编辑模式：每条右侧露出删除按钮，删前再问一次，
  **删完留在抽屉里**（想接着删下一条不用重新拉一次）
- 新建对话是列表末尾那颗加号（不是顶栏按钮）
- 全部按账号隔离，换账号看不到别人的记录
- **全删光不补空记录**：界面退回只有欢迎语的空白态，
  等用户真的再问一句，才新建记录落盘

### 七、网络感知（App 的根）

标题 **HardlySeek** 正下方一行：

- 有网：**绿点 + 在线**；没网：**红点 + 离线**
- 思考的时候，这一行被「正在想… / 正在听…」**顶掉**（同一个位置，不撑高顶栏）
- 网络状态**实时变**：开着 App 断网 8 秒内变红点，网络回来自己变绿
- 检测本身**完全不在界面上体现**，用户只会看到圆点变色
- 离线时：**本机指令照常能用**（开关手电、定提醒、算数、问时间），
  只有问答、翻译这类才回一句「现在没联网，问答用不了。」——不会在超时里干等

实现是「系统回调 + 周期自检」双保险：`NetworkCallback` 负责快，
每 5 秒（离线时 3 秒）自己问一次系统负责准——实测只靠回调时，
从有网切飞行模式界面会一直停在「在线」。

### 八、编辑与删除：只对最后一条

- **长按自己的气泡**弹「修改 / 删除」，单击不做任何事（避免误触）
- **只有最后一条发出去的消息能改能删**，改中间的会让后面的回答对不上；
  删掉最后一条后，上一条自动变成「最后一条」，以此类推
- 修改**直接在这条气泡里进行**（气泡自己变成输入框 + 保存 / 取消），不另开对话框
- **改完自动重新回答**：旧答案作废，用新问题重新问一次，界面上先看到新问题、
  再填进新答案——不会出现「问 A 答 B」
- 删除**先问一遍**确定还是取消

### 九、提醒中心（P3 伴生模块）

**闹钟优先交给系统时钟**（v5.6）：「八点叫我」「每天七点提醒」走
`AlarmClock.ACTION_SET_ALARM`，带 `SKIP_UI` 直接把闹钟建在系统时钟里——
到点响不响不再取决于我们的进程活不活。「计时 10 分钟」走 `ACTION_SET_TIMER`。
闹钟标签就是用户说的内容，响铃界面能看到。

只有手机里没有时钟应用、或系统拦了后台跳转时，才退回下面这套自研提醒，
并在回话里说清「这条靠我记着，别把应用从后台清掉」：

- SQLite 持久化 + AlarmManager 精确闹钟（Android 14+ 用 `USE_EXACT_ALARM`）
- 没精确闹钟权限时改用 `setAlarmClock`（本身就准时，代价是状态栏多个闹钟图标）
- 重复提醒（每天 / 每周）在触发瞬间就把下一次排上，不依赖下次打开 App
- 通知上直接「10 分钟后再提醒」「知道了」
- 重启 / 覆盖安装后自动重排闹钟

### 十、界面

- 顶栏：左三条杠（设置页里变返回箭头）· 中间标题 + 在线状态 · 右齿轮
- 没有底部导航、没有功能页、没有垃圾桶和刷新键
- 所有确认弹窗统一**白底黑字**：代码绘制纯白底板（`ui/Dialogs`），
  不跟系统的半透明灰底跑，深浅主题下都是同一套干净样式
- 四语言：中 / 英 / 日 / 韩（自有 `LocaleHelper`，不跟系统语言走，四语言各 103 条齐平）
- 设置只有三项：语音播报 / 语言 / 账号（外加「关于」里的模型入口和恢复默认）。
  回答方式固定成默认；唤醒那一整块已删除；无障碍权限改成**发消息时按需询问**

## 一轮问答怎么走

```
用户说话 / 打字
   │
   ▼
Dispatcher.dispatch(text, history, online)
   ├─ ① 有待确认的发送？（方案 B 之后恒为「没有」，接口留着以便单测）
   ├─ ② LocalNlu.route() 命中？ → ServiceBus.call(服务名, 参数) → 立刻有结果
   ├─ ③ LlmSwitch 关了？      → Blocked「只能做本机操作」
   ├─ ④ 没网？                → Blocked「问答用不了」
   └─ ⑤ 都不是                → AiChat.ask()
                                   ├─ system = 人设 + 当前时间 + 模式
                                   ├─ POST /chat/completions（带 32 个工具）
                                   ├─ tool_calls → AiTools → ServiceBus
                                   │              → 结果作为 role=tool 再发一轮（≤4 轮）
                                   └─ 文字答案
   ▼
上屏 + 落盘（按会话 id）+ 可选播报 + 必要时让 AI 起标题
```

## 几个关键取舍

**为什么本地只认一小撮指令**
本地规则一旦「大概猜」，就会出现「问天气答成日程」这种硬伤。
所以只认句式固定、参数明确、错了也很明显的指令，其余全部交给大模型——
漏判的代价是多一次请求，错判的代价是用户被莫名其妙地关了手电。

**为什么能力只实现一次**
v4.0 时「本地工具」和「模型工具」是两套代码，加一个能力得改两处，
还经常只有一边改到。现在总线是唯一登记处，两条入口都调同一份实现。

**为什么不留本地兜底答案**
留了就必须判断「本地这句答得够不够好」，而这个判断本身永远不准：
会出现本地硬答、把大模型的正确回答挡在外面。v4.0 直接把这条路删掉，
没网就明确告诉用户没网——诚实比虚假的可用性重要。

**为什么工具循环最多 4 轮**
模型有时会连着调十次工具（尤其它以为失败了）。4 轮足够覆盖「建提醒 → 回读确认」，
再多就是在绕圈，一次对话要烧十次请求。

**为什么不做答案缓存**
带工具调用的回答依赖「当时手机的状态」（几点、有没有提醒、电量多少）。
缓存下来的答案下次原样复活，看着像灵异事件。

**为什么网络要自己巡检**
见上文「网络感知」：只信 `NetworkCallback` 会漏掉飞行模式、Wi-Fi 连着没外网这些场景。

**为什么只有最后一条能改**
改了中间那句，它后面那串回答就全部失义。只允许改最后一条，
改完顺手作废旧答案重新问一次，上下文永远是自洽的。

**为什么发出去的话不做润色**
用户说「告诉她我晚点」和「问她吃饭了吗」，第二句是问句，但它是**要发出去的内容**。
模型很容易把问句当成人问自己的问题，于是答一句「她吃没吃我不知道」——
这正是「我发的消息被识别成提问词」。所以从抽取到工具描述都写死一条：X 原样发，
不回答、不加壳、不改语气。发出去的应该是用户的话，不是我们改写过的版本。

**为什么连打开设置面板也要验证**
`startActivity` 在后台被拦时不抛异常，所以「调用成功」根本不能当成功。
WiFi 和蓝牙在 Android 10+ 只能拉起系统面板让用户自己切，这条路径以前写的是
`startActivity` 就 `return true`——面板没起来也回「已经打开了，在上面点一下」，
用户抬头还在原地。现在统一走 `service/UiLaunch`：从 Activity 启动，
再用**本页有没有被盖住**做判据；看不见变化就如实说「系统拦了这次跳转」。
相机同理。

**为什么分享也要验证**
`startActivity` 在后台启动被拦时**不抛异常**：调用成功、界面没动。
以前在没有读屏能力时直接当成功，回一句「已经把内容带到微信了」——用户抬头一看还在原地。
现在两条验证路径（前台包名 / 我们自己被盖住）都得看见变化才算成功，
看不见就改说「已复制到剪贴板」。宁可少说一句漂亮话，也不能说一句假话。

**为什么打电话不替用户在重名里挑一个**
通讯录里两个「王伟」是很常见的事。挑错了不是「功能没做成」，是**给别人打了一个电话**——
这种错没有回退键。所以重名时一律失败并把候选说清楚，宁可多问一句。
同理，没有通讯录权限时不猜、不模糊匹配到名字相近的人，直接说「给我权限，或者说号码」。

**为什么发消息的本地规则放宽了，打电话的却收紧**
发消息错判的代价是「填错内容」，用户低头就能看见，还能改；打电话错判的代价是
「已经拨出去了」。所以发消息只要认出「平台词 + 收件人」就敢认领，
打电话却必须同时认出拨号动词和明确的对象，抽不出来就交给大模型问一句。

**为什么闹钟交给系统时钟**
自己排闹钟要同时押中三件事：进程还活着、AlarmManager 准点、通知没被关。
任何一环断了都是「闹钟没响」，而这是用户最不能接受的一种失败。
系统时钟不会被省电策略杀掉，响铃走系统通道——一次设置之后就不归我们管了。
代价是「取消闹钟」得让用户去时钟应用里关，所以回话里会直接说清楚这件事。

**为什么音量要读回来核对**
`AudioManager` 的写入接口几乎不返回结果：设了没生效、被免打扰策略挡住、
设备音量本身是固定的，全都一声不响。以前一律回「已调好」，用户看到的就是「说了没用」。
现在每次写完都读一次，没到目标就如实说「现在是几成」，并指出可能是被系统挡了。
同时把「媒体 / 铃声 / 闹钟」三条流分开——「把铃声调小」调的必须是铃声那一条。

**为什么发消息只填不发**
这是唯一会**动到别人**的操作：发错人、发错话都收不回来。
自动点发送还违反微信/QQ 的用户协议（它们按行为特征判定），风险是封号而不是不便。
所以程序只负责「打开 → 找人 → 进聊天 → 填字」，**发送键永远留给用户**。
也正因为不替人提交，就不再需要「确认吗」那一步——多问一句只是让人多说一句。

**为什么「准备」阶段不能先把微信打开**
以前是准备时就把应用拉起来、联系人搜好、字填进去，再等用户确认。
可那个时候用户已经被弹到微信里了，得自己切回来点确认、确认完再切回去看结果——
用户说的「不自动」就是这个来回。现在准备阶段只记内容，确认之后才动手，
一口气做完再自己跳回来。实测确认前前台仍是本应用，确认后连续两次启动目标应用
（含一次重试），失败才降级分享。

**为什么要校验「真的发出去了」**
点一下按钮不等于发出去了：断网、被限制、节点点错都会静默失败。
`ImAutomator.awaitSent` 会等聊天里出现这句话、或者输入框被清空，
两者都不成立就如实说失败，不编一个「已经发了」。

**为什么发消息要有两条路**
微信/QQ 会限制无障碍自动化，只押注它就会出现「权限明明开了还是发不出去」。
系统 `ACTION_SEND` 是两家公开支持的入口，不需要权限也不怕改版；
它要求用户自己选联系人，看着像退步，但恰好把最容易出错的「发给谁」
交回给人——发错人比发不出更严重。全自动成功时仍走无障碍，失败自动降级。
