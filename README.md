# HardlySeek · AI 语音助手（C3 课题）

Android 课程大作业 —— C 档「挑战级」课题 C3：本地智能语音助手。
应用在桌面上显示为 **HardlySeek**。

## 项目简介

v4.0 起，这个 App 的分工被压到最简单的三件事：**听清人话 → 交给大模型 → 需要动手就调工具**。
v5.0 又把「动手」这半件做成了**供需总线**：能力只实现一次，本地指令和大模型工具调用共用。

- **主课题**：C3 本地智能语音助手
- **伴生模块**：P3 通知提醒中心（AlarmManager 精确闹钟 + 通知操作）

做到 v3.8 时，工程里还有一整套本地规则引擎、语料库、模糊匹配、天气数据源。
它们能做「报时间、算 12 乘 8、讲个笑话」，但也仅此而已：稍微绕一点的问题就答不上，
而且**两套逻辑会互相打架**（本地先上屏、云端回来再顶掉；本地硬答，大模型插不进话）。

v4.0 把本地那套全部删掉，只留下大模型一条路。
v5.0 再把「本地优先」以另一种方式加回来：不是拿本地规则去**答题**，
而是拿它去**执行明确指令**——「开手电」「定八点提醒」「算 12 乘 8」不用联网也不用等模型，
问答、翻译、解释这些依然只有模型能做。

三个原则：

1. **能力只写一次**：一个 `Supply` 同时挂在本地路由和大模型工具上，不搞两套。
2. **本地只做确定的**：句式固定、参数明确的指令本地办；其余一律交给模型，宁可漏判不可错判。
3. **数据按账号隔离**：对话记录、提醒各自按账号分库，换账号就换一本账。

## 当前功能

### 一、强制登录

- 没有游客入口：没登录直接进登录页，返回键也退不出去
- 登录页只有品牌名和表单，不放说明性小字
- 本地账号（PBKDF2 加盐，`data/Passwords`），不联网、不上传
- 账号是数据分区的键：对话记录、提醒、设置都按账号走

### 二、语音：长按说话

底部没有麦克风按钮了。

- **按住输入框**开始收音，**松手**结束识别，**上滑**取消（滑回去还能救）
- 不按的时候**不会录任何声音**——这是和以前「连续对话」最大的区别
- 识别结果只**填进输入框**，还要点一下发送：说错了还有机会改
- 播报用系统 TTS，可在设置里关掉「语音播报」

### 三、一句话先过本地，办不了才找大模型

v5.0 加了**供需总线**：每个能力只实现一次，挂成 `域/动作`（`device/flashlight`、
`schedule/add_alarm`），**本地识别**和**大模型工具调用**落到同一份实现上。

```
用户这句话
  ├─ 有等着确认的发送？→ 「确认」就真发，说「算了」就丢
  ├─ LocalNlu 认得？   → 直接调总线，不联网、不花钱、不等待
  ├─ 云端 AI 关了？    → 直说「只能做本机操作」
  ├─ 没网？           → 直说「问答用不了」
  └─ 都不是           → AiChat.ask()，模型需要动手时再回调同一批服务
```

本地只认**句式固定、参数明确、错了也很明显**的指令，其余一律交给大模型——
「打开这个思路」不会被当成打开应用，「今天天气怎么样」不会本地硬答。
实测：断网状态下「现在几点」「打开手电筒」「12 乘 8」「提醒我明天八点交作业」
全部照常，只有问答类会回「现在没联网，问答用不了。」

| 域 | 服务 | 本地认领的说法 |
|---|---|---|
| `schedule/` | add_alarm、add_todo、query、cancel | 提醒我八点交作业 / 10 分钟后叫我 |
| `device/` | flashlight、brightness、wifi_ctrl、bluetooth_ctrl、open_app、battery | 开手电筒 / 亮度调到 60% / 打开设置页面 |
| `audio/` | tts_speak、tts_stop、asr_recognize、volume_ctrl | 大声点 / 静音 / 别念了 |
| `tool/` | calc、time、translate、weather | 帮我算 12 乘 8 / 现在几点 |
| `msg/` | send_text、confirm_send、query_can_send、query_history | 给妈妈发微信说我晚点到 |
| `study/` | word_query、word_review、explain | （交给大模型，本地不猜） |
| `gen/` | short_sentence、draft、summarize | （交给大模型） |
| `context/` | clear、switch_prompt | 清空上下文 / 切到消息模式 |
| `kws/` | start、stop、set_wake_word、set_sensitivity、set_session_timeout | （设置页开关，也能被模型调） |
| `llm/` | toggle | 关掉云端 AI |

模型那头只暴露 18 个工具（`schedule_add_alarm` 这种下划线写法，网关切 `/` 会 400），
`AiTools` 负责在两种命名之间来回翻译。

### 四、发消息：微信 / QQ 自动化（默认只准备，不发送）

微信没有对外开放的接口，所以走**无障碍模拟点击**这条唯一可行的路：

```
给妈妈发微信说我晚点到
  → 打开微信 → 搜索「妈妈」→ 进聊天 → 把内容填进输入框（**停在这里**）
  → 「给「妈妈」发：我晚点到，确认吗？」
  → 用户说「确认」才真的点发送
```

- **必须二次确认**：钉在 `msg/send_text` 里而不是界面上——不然模型一次调用就直接发出去了
- 联系人**找不到就失败**，不问「是不是这个」；重名也不自己挑
- 每次准备生成 `trace_id`，重复确认不会重复发
- 设置页「自动发消息权限」直接跳到系统无障碍页，让用户自己勾

风险如实写在这里：自动化发微信违反其用户协议，高频使用有账号风险；
微信改版也会让节点失效。所以只做低频、本人主动触发、带确认的用法。

### 五、唤醒词：两级唤醒

```
① 休眠：前台服务跑系统识别循环，等「小豆小豆」
      ↓ 命中（可调灵敏度，默认允许只喊前两个字）
② 会话窗口：60 秒内可以直接说话，不用再喊；超时回 ①
```

**这不是低功耗 KWS**，是用系统识别引擎循环监听——耗电明显高于讯飞离线唤醒，
部分机型离线识别包不全时会走网络。好处是零新增依赖、接口（`kws/…`）与真 KWS 一致，
将来换引擎不用改调用方。默认关闭，设置里一个开关，开着会常驻一条通知。

### 六、多会话（对话记录）

左上角三条杠拉开左侧抽屉（占屏宽 4/5）。抽屉出来时，后面的对话会**真的糊掉**
（Android 12+ 用 `RenderEffect`；老系统退回加深遮罩），视线自然落在列表上。

- 每条对话**由 AI 起标题**（另发一次很小的请求，失败就用首句前 12 个字）
- 每条对话**相互独立**：独立的上下文、独立的落盘键
- 点一条切过去。**长按任意一条**，或点右上角那颗白底黑字的「编辑」，
  都能进编辑模式：每条右侧露出删除按钮，删前再问一次，
  **删完留在抽屉里**（想接着删下一条不用重新拉一次）
- 新建对话是列表末尾那颗加号（不是顶栏按钮）
- 全部按账号隔离，换账号看不到别人的记录
- **全删光不补空记录**：界面退回只有欢迎语的空白态，
  等用户真的再问一句，才新建记录落盘

### 七、网络感知（App 的根）

标题 **HardlySeek** 正下方一行：

- 有网：**绿点 + 在线**；没网：**红点 + 离线**
- 思考的时候，这一行被「正在想… / 正在听…」**顶掉**（同一个位置，不撑高顶栏）
- 网络状态**实时变**：开着 App 断网 8 秒内变红点，网络回来自己变绿
- 检测本身**完全不在界面上体现**，用户只会看到圆点变色
- 离线时：**本机指令照常能用**（开关手电、定提醒、算数、问时间），
  只有问答、翻译这类才回一句「现在没联网，问答用不了。」——不会在超时里干等

实现是「系统回调 + 周期自检」双保险：`NetworkCallback` 负责快，
每 5 秒（离线时 3 秒）自己问一次系统负责准——实测只靠回调时，
从有网切飞行模式界面会一直停在「在线」。

### 八、编辑与删除：只对最后一条

- **长按自己的气泡**弹「修改 / 删除」，单击不做任何事（避免误触）
- **只有最后一条发出去的消息能改能删**，改中间的会让后面的回答对不上；
  删掉最后一条后，上一条自动变成「最后一条」，以此类推
- 修改**直接在这条气泡里进行**（气泡自己变成输入框 + 保存 / 取消），不另开对话框
- **改完自动重新回答**：旧答案作废，用新问题重新问一次，界面上先看到新问题、
  再填进新答案——不会出现「问 A 答 B」
- 删除**先问一遍**确定还是取消

### 九、提醒中心（P3 伴生模块）

- SQLite 持久化 + AlarmManager 精确闹钟（Android 14+ 用 `USE_EXACT_ALARM`）
- 重复提醒（每天 / 每周）在触发瞬间就把下一次排上，不依赖下次打开 App
- 通知上直接「10 分钟后再提醒」「知道了」
- 重启 / 覆盖安装后自动重排闹钟

### 十、界面

- 顶栏：左三条杠（设置页里变返回箭头）· 中间标题 + 在线状态 · 右齿轮
- 没有底部导航、没有功能页、没有垃圾桶和刷新键
- 四语言：中 / 英 / 日 / 韩（自有 `LocaleHelper`，不跟系统语言走）
- 设置只留最常用的：回答方式 / 语音播报 / 语音唤醒 / 自动发消息权限 / 语言 / 账号 / 关于

### 十一、外部调用入口

```bash
adb shell am start -n com.example.voiceassistant/.ui.VoiceAssistantActivity --es query "现在几点"
```

`launchMode=singleTop` + `onNewIntent`，连续调用也在同一段对话里，上下文不断。

## 一轮问答怎么走

```
用户说话 / 打字
   │
   ▼
Dispatcher.dispatch(text, history, online)
   ├─ ① 有待确认的发送？──「确认」→ msg/confirm_send
   │                    └「算了」→ 丢掉待发内容
   ├─ ② LocalNlu.route() 命中？ → ServiceBus.call(服务名, 参数) → 立刻有结果
   ├─ ③ LlmSwitch 关了？      → Blocked「只能做本机操作」
   ├─ ④ 没网？                → Blocked「问答用不了」
   └─ ⑤ 都不是                → AiChat.ask()
                                   ├─ system = 人设 + 当前时间 + 模式
                                   ├─ POST /chat/completions（带 18 个工具）
                                   ├─ tool_calls → AiTools → ServiceBus
                                   │              → 结果作为 role=tool 再发一轮（≤4 轮）
                                   └─ 文字答案
   ▼
上屏 + 落盘（按会话 id）+ 可选播报 + 必要时让 AI 起标题
```

## 分层与目录结构

```
app/src/main/java/com/example/voiceassistant/
├── core/Dispatcher.kt      路由：这句话本地办、拦下、还是交给大模型
├── core/AiChat.kt          一轮问答的全部智能：组消息、发请求、转工具、收敛回答
├── core/LlmBridge.kt       给供给方用的「问一句模型」：翻译、解释、写文案
├── bus/ServiceBus.kt       供需总线：Supply / BusArgs / BusReply / 服务注册表
├── nlu/                    本地识别：LocalNlu（规则）、Calc（算式）、TimeWords/TimeParse（时间）
├── provider/               各域供给方：schedule / device / audio / tool / study / gen / context / msg / kws
├── im/                     微信 QQ 自动化：无障碍服务 + 状态机
├── kws/                    唤醒词：匹配规则 + 前台服务
├── tool/AiTools.kt         协议适配：18 个工具的声明 + 名字/参数双向转换
├── handler/llm/            云端配置、协议解析、人设、连通性测试
├── network/                网络状态感知 + HTTP
├── data/                   账号 / 会话 / 会话存储 / 设置 / 消息模型
├── reminder/               提醒中心（P3）：模型、SQLite、状态机、闹钟、广播
├── service/                ASR / TTS / 设备与音频控制 / 应用名表
├── installer/              装完清理安装包
└── ui/                     只做接线：Activity / ChatFragment / 两个 Adapter / 登录 / 设置
```

层与层之间只认两个接口：`reminder/ReminderPort`（提醒）和 `bus/Supply`（能力）。
加一个能力 = 写一个 `Supply` + 在 `AiTools.SCHEMA` 补一段描述，
本地和大模型两条路同时就有了；想换存储、换模型都不用动调用链。

## 几个关键取舍

**为什么本地只认一小撮指令**
本地规则一旦「大概猜」，就会出现「问天气答成日程」这种硬伤。
所以只认句式固定、参数明确、错了也很明显的指令，其余全部交给大模型——
漏判的代价是多一次请求，错判的代价是用户被莫名其妙地关了手电。

**为什么能力只实现一次**
v4.0 时「本地工具」和「模型工具」是两套代码，加一个能力得改两处，
还经常只有一边改到。现在总线是唯一登记处，两条入口都调同一份实现。

**为什么不留本地兜底答案**
留了就必须判断「本地这句答得够不够好」，而这个判断本身永远不准：
会出现本地硬答、把大模型的正确回答挡在外面。v4.0 直接把这条路删掉，
没网就明确告诉用户没网——诚实比虚假的可用性重要。

**为什么工具循环最多 4 轮**
模型有时会连着调十次工具（尤其它以为失败了）。4 轮足够覆盖「建提醒 → 回读确认」，
再多就是在绕圈，一次对话要烧十次请求。

**为什么不做答案缓存**
带工具调用的回答依赖「当时手机的状态」（几点、有没有提醒、电量多少）。
缓存下来的答案下次原样复活，看着像灵异事件。

**为什么网络要自己巡检**
见上文「网络感知」：只信 `NetworkCallback` 会漏掉飞行模式、Wi-Fi 连着没外网这些场景。

**为什么只有最后一条能改**
改了中间那句，它后面那串回答就全部失义。只允许改最后一条，
改完顺手作废旧答案重新问一次，上下文永远是自洽的。

**为什么唤醒词不用真 KWS**
讯飞离线唤醒要 AppID + 唤醒资源包，sherpa-onnx 要引 so 和模型文件；
先用系统识别循环把「两级唤醒」的体验和接口跑通（`kws/…` 与真 KWS 一致），
将来换引擎只替换 `WakeWordService`，调用方一行不用改。代价是费电，所以默认关。

**为什么发消息必须先复述再确认**
这是唯一会**动到别人**的操作：发错人、发错话都收不回来。
所以 `msg/send_text` 只准备不发送，「确认」走单独的 `msg/confirm_send`——
钉在服务里而不是界面上，模型调用也绕不过去。

## 测试

```bash
./gradlew testDebugUnitTest --offline   # 178 个单测，全绿
./gradlew lintDebug --offline           # 0 error
```

单测只测**纯函数**（不需要 Android 运行时）：

- `LocalNluTest`：每句话该去哪——手电、开应用、音量、提醒、算式、发消息，
  以及「必须放给大模型」的那一批
- `TimeWordsTest` / `TimeParseTest`：中文时间（晚上八点 / 明早 / 周三下午两点 /
  半小时后）与机器格式；说过了点就顺延，说不清就返回 null
- `CalcTest`：优先级、负数、乘方右结合、除零、语法错；
  「12」和「1个苹果多少钱」都不能被认成算式
- `ServiceBusTest`：注册覆盖、找不到服务、供给方抛异常、名字双向转换
- `DispatcherTest`：确认优先、本地优先（断网也能用）、关了 AI / 没网怎么回、
  以及「带着后续指令的好」不能被当成确认
- `AiToolsTest`：18 个工具是合法 JSON 且与总线服务一一对得上、名字只换第一个下划线
- `AiChatTest`：请求体结构、工具调用解析（标准 / 旧式两种写法）、起名兜底
- `ChatSessionTest`：改问之后旧答案作废、历史只取这条之前、上下文不断
- `ConversationStoreTest`：会话与消息的编解码（引号换行不能把数据写坏）
- `CloudLlmHandlerTest`：地址拼接、JSON 转义、错误翻译、三代旧人设迁移
- `ReminderCenterTest` / `ReminderRepeatTest`：提醒状态机与重复规则
